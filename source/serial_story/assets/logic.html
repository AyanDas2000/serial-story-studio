The author directs the story

As a serial grows, the model and author have more context to track. The desk separates governing direction, planned episodes, editable drafts, approved prose and source-linked facts. It gives the author explicit control over adoption, editing, approval and corrections.

The current loop

  1. Adopt the story direction and episode plan.
  2. Freeze a drafting request with the direction, episode goal, style and exact earlier prose.
  3. Generate a draft in practice mode or through Merge Gateway. A draft is not approved story text.
  4. Edit, save and approve the exact prose. Approval locks that revision.
  5. Preview extracted facts, inspect their source quotes and explicitly confirm them.

Control and recovery

Edits create revisions. Changing earlier draft text flags dependent later work for review. Version checks stop stale results replacing current work. Provider calls run outside database transactions; uncertain outcomes pause for human resolution instead of automatic retries.

Length and spending

Studio, Length sets the shortest, target and longest episode size for future requests. It does not rewrite existing prose or guarantee model compliance. Live calls reserve estimated cost and settle afterward. The local spending limit is per series; the supplied key's provider-side limit is separate.

What remains unfinished

The Memory ledger supports author inspection and does not feed the writer. Draft requests still include all earlier prose. Bounded retrieval, semantic consistency checking and demonstrated 200-episode behavior remain unfinished. The protected-secret check matches words, not ideas.

Development approach

This project was built largely using LLM-powered coding tools. Ayan defined the core logic, workflow and design decisions and directed the iterations; not every component was manually implemented by Ayan.
