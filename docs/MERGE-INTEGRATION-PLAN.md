## Official specification findings checked by parent

- Chat reference: `https://docs.merge.dev/merge-gateway/api-overview/chat-completions/create`. Route is `/v1/chat/completions`; canonical model plus a single `vendor` restricts the route. The request supports token limits, standard tier, disabled tier fallback and routing metadata. Use no tools/priority lists.
- Routing reference: `https://docs.merge.dev/merge-gateway/routing/using-policies`. Concrete model IDs bypass policies. Priority lists can create inline policies, so do not send them. Pin one vendor rather than an ordered fallback list; the application itself makes only one attempt.
- API overview: `https://docs.merge.dev/merge-gateway/api-overview`. Non-streaming response headers identify the serving model/vendor and request ID. `usage.cost` is provider cost; routing adds a separate Merge fee when exposed. Missing/unpriced numbers are not zero. Server tools can add charges, so they are excluded.
- Pricing reference: `https://docs.merge.dev/merge-gateway/cost/pricing`. Pro has a 5% fee; Enterprise uses contracted terms. The invoice remains authoritative. Treat unverified plan terms conservatively, not as guaranteed promotional free use.
